- One visible browser shared by the human and the agent, driven by typed tools. The MCP frontend is a thin relay to a background daemon; Edge on Windows, bundled Chromium on Linux.
- Agent surface: observe, act, batch, search, tabs, diagnostics, takeover, storage, plus `browser_read` (the page as text, markdown, links, or html) and `browser_js` (expression escape hatch).

- 2026-10-21 (commits 6d34ab, 6caa296, 6a9b702, 8213795): the agent surface was made cheaper and more accurate, each change with a test that fails without it.
- The read path used to take no wait at all, so a read straight after a navigation could hand the agent an empty or half page. A read now waits for the page to stop fetching (bounded at half a second); a page that has already settled costs nothing. The same wait covers a name lookup that misses: a control that arrives with the page's own data was not in the registry yet.
- A batch has a `wait` step now (text visible, URL contains, control visible, control enabled - the same conditions the wait op uses). "Wait for the control, then fill it" is one call and one queue slot, so the page cannot change between the wait and the act.
- `tests/benchmarks/tasks.test.ts` measures what a web task costs an agent in tool calls: six tasks (search, read, form, late control, redirect, links) with a per-task budget, and any tool-induced failure (stale ref, name not found, page moved under the action) fails the task. It writes `results/tasks.json` and a table in REPORT.md. Baseline: 13 calls over 6 tasks, 0 tool-induced failures.

The daemon's `/v1/health` reports `builtAt`, but it is read per request, so it shows the file's current mtime and not the age of the running code.

- 2026-11-01 audit (read-only, 4 parallel reviewers, tree at dd1c517) of the 10 issues in `browser-bridge-issues.md`. - 2026-11-01 (landed): the session idle lease. A session records the MCP connection that created it (`peer`) and the time of its last enqueued operation (`lastUsedAt`). `releasePeer()` orphans exactly that connection's sessions when its socket closes. A sweep closes ownerless, unpaused sessions idle past the lease — 15 minutes by default, `BRIDGE_SESSION_TTL_MS` overrides, `0` disables, an unparseable value falls back to the default rather than reaping everything. `inventory()` now reports `client` (null when the owner is gone), `paused`, `idleMs` and `profile`. Six contract tests in `tests/contract/lease.test.ts`; two of them fail with the sweep disabled.
- 2026-11-01: `closeSession` is no longer queued behind the work it ends. It waits at most 5 s for the running op (`CLOSE_GRACE_MS`), then tears down; two callers share one `closePromise`; work accepted before close still finishes, work accepted after it is refused by `closing`. No generation bump — that cancelled reads already accepted, caught by the existing contract test `finishes reads queued before close without rejecting them as closing`.
- 2026-11-01: the daemon's idle-retire check re-arms itself while sessions remain, instead of firing once and giving up. Without that, the lease could close the last session and the daemon would still never notice.
- 2026-11-01: two agents on one browser needs no new surface. Each `browser_start` is its own `BrowserContext`, and with `viewport: null` every headed tab is its own OS window (measured: window ids 1, 2, 3 for two contexts and a second tab). What was missing was ownership and time, which the lease now supplies. Acting inside another session's tab stays out on purpose: a tab lives in a context, so that would mean acting inside another agent's cookies.
- 2026-11-01 (landed): the ref epoch. `tab.refEpoch` advances only when the control list changes (`controlKey` over the collected targets), while `tab.revision` still advances per observation for screenshot geometry and delta history. Refs are minted as `el-<epoch>-<n>`, validity is `issued.get(ref) === refEpoch`, and `resume` forces a new epoch so a human takeover still retires every ref. `assertConditionRefCurrent` makes a wait on a stale ref fail `STALE_OBSERVATION` instead of burning its timeout. This supersedes the blunt F1 rule; the hard gate stays. Two existing tests encoded the old rule and were rewritten to a real element-set change (`widgets.test.ts`) and the resume exception (`takeover.test.ts`).
- 2026-11-01 (landed): `browser_js` awaits a returned promise, bounded at 10 s in the page (`EXPRESSION_TIMEOUT_MS`) so a never-settling script returns an error instead of wedging the queue. `eval` joined `reportsNavigation`, the call reports `navigation`, returns the fresh observation (its refs were retired anyway), and probes the execution context after the expression so a scripted navigation is waited for before the refresh reads the page.
