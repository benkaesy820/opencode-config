- 2026-11-02: built at `/home/benkaesy/Projects/research-bridge` by the Penny Pincher subagent. Rust, single binary, MCP over stdio.
- 2026-11-02: installed binary `~/.local/bin/research-bridge` (5.0 MB), rebuilt 15:48 after concurrency/links/cache work. Idle RSS ~6.0 MB, 14 threads.
- Eight tools: `research_start`, `research_search`, `research_read`, `research_source`, `research_note`, `research_status`, `research_report`, `research_list`.
- Storage: `~/.local/share/research-bridge/<sessionId>/` with `session.json`, `searches.jsonl`, `sources.jsonl`, `claims.jsonl`, `sources/SN.txt`, `sources/SN.links.json`, `report.md`.
- Trust gate: `research_note` accepts a claim only when its quote is an exact substring of the stored source after whitespace normalization; `research_report` re-verifies every quote and excludes unverified claims.
- Search: DuckDuckGo HTML, then DuckDuckGo Lite fallback; optional self-hosted SearXNG via `SEARXNG_URL`. Successful results cached in-process 10 min. No API key.
- Read: HTML/text/JSON/PDF; HTML via `scraper` (Servo html5ever), PDF via `pdftotext`, PDF title skips licence/arXiv boilerplate. `research_read` returns up to 40 content links and reuses an already-stored source unless `refresh: true`. No browser, JavaScript, login, paywall, or OCR.
- Security: public http/https only; localhost/private/link-local/CGNAT blocked unless `RESEARCH_ALLOW_PRIVATE=1`; manual redirects; size caps; untrusted external content. No anti-bot bypass: Mojeek serves a captcha, Marginalia's public API key returned 429 twice, and both DuckDuckGo endpoints challenge intermittently.
- Wired into `~/.config/opencode/opencode.json` as `mcp.servers.research-bridge-v2` (the old `research-bridge` entry was removed after a stale process failure), command `~/.local/bin/research-bridge`, env `RESEARCH_HOME`. `opencode mcp list` reports **connected**.

- 2026-11-02: extraction issue found during Linux 7.4 research, logged for the next fix pass. `research_read` of `https://www.fosslinux.com/163274/linux-7-4-features.htm` returned 27,932 chars but `linkCount: 0`, while the page's `<article>` contains 33 anchors. Cause: `collect_links` calls `is_in_chrome`, which walks ancestors past the collected root to `<html>`; the site wraps everything in `<div class="wrapper-boxed header-style-header-1 ...">`, whose class tokenizes to `header`, so every anchor is classified as chrome. The same wrapper pattern can drop body text on pages without `main`/`article`. Fix direction: bound the ancestor walk at the content root and match chrome words against whole class names or trailing segments, not every hyphen segment. Add a fixture with a wrapper class containing `header` and assert links survive.
